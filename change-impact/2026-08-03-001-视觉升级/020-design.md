## 1. 设计概览

设计方向：**深墨大屏上，朱砂红的巨型首推名带着金色光晕浮现**——像一块揭开的牌匾，是直播中观众一眼记住的瞬间。全站深墨底 `#0E1714`，米白正文保证可读性，金色用于线条与描边，朱砂红只用在最强强调（首推名、CTA、错误）。保留 Noto Serif SC 衬线字体（900 超重做巨型字），动效克制地做开场浮现与生成推进，尊重系统减弱动态设置。摘要图 PNG 同步深色风，与线上页气质一致。

## 4. 代码风格报告

项目采用 Tailwind CSS 原子类为主、`globals.css` 提供少量组件类（`field-input` / `btn-primary` / `btn-ghost` / `btn-gold` / `ink-divider`）。页面都是 Server Component 外壳 + 路由同目录的 `"use client"` 表单组件（login-form / naming-form），共享壳组件放 `src/components`。字体统一 Noto Serif SC 衬线。组件类集中在 globals.css，不散落。本次变更遵循同样结构：设计 token 集中在 tailwind 配置与 globals.css 组件类，页面用原子类组合；`data-testid` 全部保留。

### 实施阶段风格约束

| style_axes 轴名 | 从代码确认的约束内容 |
|-----------------|---------------------|
| styling | Tailwind 原子类 + globals.css 组件类；token 集中在配置，不散落硬编码色值 |
| rendering_boundary | 页面保持 Server Component，交互表单保持 `"use client"` 与路由同目录 |
| naming | 组件类命名沿用 `btn-*` / `field-*` 前缀风格 |
| test | 全部 data-testid 原样保留；e2e 不改逻辑 |
| accessibility | 焦点可见、对比度 AA、尊重 prefers-reduced-motion |

## 5. 替代方案与权衡

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| A: 仅报告页升级 | 只改最核心的报告页 | 改动小、风险低 | 其他页风格割裂，直播切换画面跳戏 | 视觉不统一 |
| B: 亮色现代风 | 保留浅底加强对比 | 改动幅度小 | 浅底在直播屏上聚焦度不如深色 | 吸睛不足 |
| C: 新增直播模式页 | 单独做一个全屏展示页 | 观赏性最强 | 工作量大、需新页面/新路由 | 超范围 |
| → 选了 深色全页统一升级，理由：用户已确认全部页面统一 + 深色大屏，投屏场景下深色最能聚焦目光，且不加新页面控制范围 |

## 8. 设计原则约束

- **简单优先**：不加直播模式页、不加组件库、不加配置项，只做用户要求的视觉升级
- **精准修改**：只改 12 个 UI 文件样式与文案，不"改进"相邻代码、不重构后端
- **质量底线**：深色风达到项目同等质量——对比度 AA、焦点可见、动效克制、测试契约保留
- **语义约定**：按钮文案从「进入」改「登录」属文案修改（非 enum/状态），已获用户确认

### 行为准则检查

- 任务规模：大（12+ 文件）
- 适用规则：前 7 条 + 复杂链路覆盖表（context-pack §4 + 本设计 §3）
- 精准修改边界：仅 UI 层 12 文件，不碰 domain/store/auth/api/providers
- 不做的事：不加新页面/新路由、不改 API/存储/认证、不更新 docs
- 语义约定证据：按钮文案改动有 e2e 失败事实依据 + 用户确认
- 测试策略依据：UI 改动 e2e 必须通过；单测回归确认
